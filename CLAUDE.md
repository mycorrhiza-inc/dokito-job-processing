- This dokito project is built out of a nix project with the root at flake.nix If you are ever confused about how the entire project is glued together check this file. If you ever are confused about what binaries this builds please run `nix flake show` to get an up to date description.
- NOTE: When you create new files they will first need to be added to git before nix will understand they exist. Once they are created you do not need to commit extra changes for nix to track them.
- The directory playwright/ is used to handle typescript web scraping utilities, and is built as a module by the main.nix file in that directory combined with the root flake. Importantly if you ever ever want to test if a binary either compiles with typescript or execute a test run of a script do `nix run .#ny-puc -- --mode ids_only --fetch-all-docket-metadata`. Do not run traditional typescript commands since they often wont work, and its crucial that the nix pipeline remain bug free.
- The same is true of the rust-data-transforms/ directory. It builds a bunch of different binaries that are defined in Cargo.toml, and are then built by main.nix and the main flake. Importantly if you ever ever want to test if the project either compiles or execute a test run `nix run .#database-utils -- list-docket-ids --fixed-jur new_york
_puc ` or `nix build .#database-utils`.
- Most importantly the runner/ directory is a golang project that goes ahead and glues the other projects together. This is done by taking in environment variables to the outputs of playwright/ and rust-data-transforms/ by first compiling the CLI and SERVER binaries. It is hypothetically possible to build these with golang, but it will not work because the rust and typescript dependancies will not be executed. The only way you should ever run or test to see if this project compiles is with `nix build .#server` or `nix run .#cli -- bulk-queue --limit=100 --source=html`
